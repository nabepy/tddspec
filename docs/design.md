# 設計書: 在庫つき注文受付（サンプル）

> 試作用のサンプル設計書。人間が書いた設計書という位置づけで、要求には REQ-ID を振る。
> 要求を変えるときは、この設計書と `trace.json` の `requirements` を一緒に更新する。

## 1. 目的
小さな店舗の在庫を管理し、在庫の範囲で注文を受け付ける。

## 2. 用語
- 商品: SKU（文字列）で識別する。
- 在庫数: 商品ごとの、すぐに引き当てられる個数（0以上の整数）。
- 注文: 1つの商品を1以上の数量で注文する。受け付けると注文IDが発行される。

## 3. 要求

| ID | 要求 |
|---|---|
| REQ-001 | 商品を SKU と在庫数を指定して登録できる。登録済みの SKU を再登録すると在庫数を上書きする。 |
| REQ-002 | 商品の現在の在庫数を照会できる。 |
| REQ-003 | 注文数量が在庫数以下なら注文を受け付け、注文IDを返し、在庫数を注文数量だけ減らす。 |
| REQ-004 | 注文数量が在庫数を超える注文は拒否する。拒否した注文で在庫数は変わらない。 |
| REQ-005 | 受け付けた注文をキャンセルすると、その注文の数量を在庫数に戻す。 |
| REQ-006 | 在庫数がしきい値（既定5）を下回った商品を一覧できる。 |

## 4. 未規定の点（設計の余白）
- REQ-004 の「拒否する」の方法（例外にするか、結果として返すか）は決めていない。
- 数量0や負の数量の注文、存在しない SKU への注文、同じ注文の二重キャンセルの扱いは決めていない。
